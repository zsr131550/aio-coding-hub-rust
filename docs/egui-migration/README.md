# egui migration evidence

This directory is the versioned C0 evidence boundary for the native egui migration. It describes the current Tauri/React shell before any `eframe`, `egui`, `winit`, or core extraction work begins.

## Artifacts

- `compatibility-contract.json`: deterministic machine-readable snapshot of app identity, routes, 195 generated commands plus one runtime-only updater command, risky confirmations, events, data schemas, Plugin API v1, and release targets.
- `compatibility-matrix.md`: route and global-surface behavior that the egui shell must preserve.
- `baseline-protocol.md`: exact release-build, fixture, process-tree, UI action, and gateway-load measurement protocol.
- `baselines/`: immutable per-machine, per-scenario raw results. macOS and Linux remain pending until run on those platforms.
- `src-tauri/tests/fixtures/egui-migration/`: synthetic SQLite, settings, 10k logs, Plugin API, Extension Host, and updater inputs consumed by the protocol.
- `src/services/{app,gateway}/__fixtures__/`: shared event payload fixtures. Rust tests compare them by exact JSON value against the production Serde payload types/builders; frontend contract tests consume the same files where runtime guards exist.

## Contract commands

```powershell
pnpm check:egui-compat-contract
pnpm check:egui-fixtures
pnpm test:egui-baseline-self
pnpm test:egui-baseline-matrix-self
pnpm check:egui-baseline-registry
```

Snapshot changes are explicit:

```powershell
pnpm egui:compat-contract:write
pnpm egui:fixtures:write
```

Review the resulting diff. Do not edit generated JSON or fixture hashes by hand.

`check:egui-fixtures` scans every committed artifact, including readable bytes
inside SQLite files, for non-empty credential fields, token/private-key
material, and absolute personal home paths before it verifies generated bytes
or `manifest.json`. The current settings fixture intentionally keeps
`enable_notification_sound=false` as a safe non-default value; its exact
canonical shape is parsed and bounds-checked by the production Rust settings
code.

## Rust-backed fixture regeneration

The current SQLite database, both SQLite schema snapshots, and current settings are
exported by the ignored Rust test
`egui_fixture_contract::export_current_egui_database_fixture`. The test reads the
committed SQLite v25 database as its authoritative input; it does not regenerate
that database.

The exporter requires one explicit staging root and three output environment
variables:

- `AIO_EGUI_FIXTURE_STAGING_ROOT`: existing absolute staging directory.
- `AIO_EGUI_CURRENT_DB_OUTPUT`: generated current SQLite database.
- `AIO_EGUI_V25_SCHEMA_OUTPUT`: generated schema snapshot for the committed v25 database.
- `AIO_EGUI_SETTINGS_OUTPUT`: generated canonical current settings JSON.

Rust derives the current schema as a fourth output with
`Path::with_extension("schema.json")`, so an output named `aio-coding-hub.db`
creates `aio-coding-hub.schema.json`, not `schema.json`. Before writing anything,
the exporter requires all four final output paths to be absolute, distinct,
absent, and beneath the canonical staging root. Output parent directories must
already exist. This check resolves parent aliases, including links and `..`, so
an aliased path cannot overwrite the derived sidecar. Always use a new empty
system-temporary staging directory. Never point the staging root or output paths
at the committed fixture tree.

Run this safe rehearsal from a fresh PowerShell at the repository root. It sets
`CARGO_BUILD_JOBS=1`, validates the exact Rust output set, assembles a complete
candidate tree under the same temporary root, and runs fixture write/check only
against that candidate. It does not modify committed fixtures.

```powershell
$repo = (Resolve-Path ".").Path
$committed = Join-Path $repo "src-tauri\tests\fixtures\egui-migration"
$tempRoot = Join-Path ([IO.Path]::GetTempPath()) `
  ("aio-egui-fixtures-" + [guid]::NewGuid().ToString("N"))
New-Item -ItemType Directory -Path $tempRoot | Out-Null
if (@(Get-ChildItem -Force -LiteralPath $tempRoot).Count -ne 0) {
  throw "temporary fixture root is not empty: $tempRoot"
}

$rustStage = Join-Path $tempRoot "rust"
$sandboxRoot = Join-Path $tempRoot "sandbox"
$candidate = Join-Path $sandboxRoot "src-tauri\tests\fixtures\egui-migration"
New-Item -ItemType Directory -Path $rustStage | Out-Null

$currentDb = Join-Path $rustStage "aio-coding-hub.db"
$currentSchema = [IO.Path]::ChangeExtension($currentDb, "schema.json")
$v25Schema = Join-Path $rustStage "sqlite-v25.schema.json"
$settings = Join-Path $rustStage "settings-current.json"
$expectedRust = @($currentDb, $currentSchema, $v25Schema, $settings)

foreach ($path in $expectedRust) {
  if (-not [IO.Path]::IsPathRooted($path) -or [IO.Path]::GetFullPath($path) -ne $path) {
    throw "fixture output is not absolute: $path"
  }
  if (Test-Path -LiteralPath $path) {
    throw "fixture output already exists: $path"
  }
}

$environmentNames = @(
  "CARGO_BUILD_JOBS",
  "AIO_EGUI_FIXTURE_STAGING_ROOT",
  "AIO_EGUI_CURRENT_DB_OUTPUT",
  "AIO_EGUI_V25_SCHEMA_OUTPUT",
  "AIO_EGUI_SETTINGS_OUTPUT"
)
$oldEnvironment = @{}
foreach ($name in $environmentNames) {
  $oldEnvironment[$name] = [Environment]::GetEnvironmentVariable($name, "Process")
}

try {
  [Environment]::SetEnvironmentVariable("CARGO_BUILD_JOBS", "1", "Process")
  [Environment]::SetEnvironmentVariable("AIO_EGUI_FIXTURE_STAGING_ROOT", $rustStage, "Process")
  [Environment]::SetEnvironmentVariable("AIO_EGUI_CURRENT_DB_OUTPUT", $currentDb, "Process")
  [Environment]::SetEnvironmentVariable("AIO_EGUI_V25_SCHEMA_OUTPUT", $v25Schema, "Process")
  [Environment]::SetEnvironmentVariable("AIO_EGUI_SETTINGS_OUTPUT", $settings, "Process")

  Push-Location (Join-Path $repo "src-tauri")
  try {
    cargo test --locked --lib `
      egui_fixture_contract::export_current_egui_database_fixture -- `
      --ignored --exact --nocapture
    if ($LASTEXITCODE -ne 0) { throw "Rust fixture export failed" }
  } finally {
    Pop-Location
  }
} finally {
  foreach ($name in $environmentNames) {
    [Environment]::SetEnvironmentVariable($name, $oldEnvironment[$name], "Process")
  }
}

$missing = @($expectedRust | Where-Object { -not (Test-Path -LiteralPath $_ -PathType Leaf) })
$actual = @(
  Get-ChildItem -LiteralPath $rustStage -File -Recurse |
    ForEach-Object { $_.FullName }
)
$unexpected = @($actual | Where-Object { $_ -notin $expectedRust })
if ($missing.Count -ne 0 -or $unexpected.Count -ne 0) {
  throw "unexpected Rust output set; missing=$($missing -join ', '); unexpected=$($unexpected -join ', ')"
}
Get-Item -LiteralPath $expectedRust | Select-Object FullName, Length
Get-FileHash -Algorithm SHA256 -LiteralPath $expectedRust
```

Inspect the four file names, sizes, and hashes before moving them. Then assemble
the isolated candidate. Every destination is checked before the move; the only
copied Rust artifact is the authoritative committed v25 database.

```powershell
$candidateV25Dir = Join-Path $candidate "data\sqlite-v25"
$candidateCurrentDir = Join-Path $candidate "data\sqlite-current"
$candidateSettingsDir = Join-Path $candidate "settings"
New-Item -ItemType Directory -Force -Path `
  $candidateV25Dir, $candidateCurrentDir, $candidateSettingsDir | Out-Null

$candidateV25Db = Join-Path $candidateV25Dir "aio-coding-hub.db"
$candidateV25Schema = Join-Path $candidateV25Dir "schema.json"
$candidateCurrentDb = Join-Path $candidateCurrentDir "aio-coding-hub.db"
$candidateCurrentSchema = Join-Path $candidateCurrentDir "schema.json"
$candidateSettings = Join-Path $candidateSettingsDir "settings-current.json"
$sandboxPackage = Join-Path $sandboxRoot "package.json"
$candidateOutputs = @(
  $candidateV25Db,
  $candidateV25Schema,
  $candidateCurrentDb,
  $candidateCurrentSchema,
  $candidateSettings,
  $sandboxPackage
)
if (@($candidateOutputs | Where-Object { Test-Path -LiteralPath $_ }).Count -ne 0) {
  throw "candidate destination already exists"
}

Copy-Item -LiteralPath (Join-Path $repo "package.json") -Destination $sandboxPackage
Copy-Item -LiteralPath `
  (Join-Path $committed "data\sqlite-v25\aio-coding-hub.db") `
  -Destination $candidateV25Db
Move-Item -LiteralPath $v25Schema -Destination $candidateV25Schema
Move-Item -LiteralPath $currentDb -Destination $candidateCurrentDb
Move-Item -LiteralPath $currentSchema -Destination $candidateCurrentSchema
Move-Item -LiteralPath $settings -Destination $candidateSettings

Push-Location $repo
try {
  pnpm egui:fixtures:write --root $sandboxRoot
  if ($LASTEXITCODE -ne 0) { throw "candidate fixture write failed" }
  pnpm check:egui-fixtures --root $sandboxRoot
  if ($LASTEXITCODE -ne 0) { throw "candidate fixture check failed" }

  git diff --no-index --stat -- $committed $candidate
  if ($LASTEXITCODE -gt 1) { throw "candidate fixture stat failed" }
  git diff --no-index -- $committed $candidate
  if ($LASTEXITCODE -gt 1) { throw "candidate fixture diff failed" }
} finally {
  Pop-Location
}
```

`git diff --no-index` returns `1` when the candidate contains expected changes;
that is a review result, not an execution failure. Keep `$tempRoot` until the
candidate diff is approved. Only then move the reviewed candidate artifacts into
`src-tauri/tests/fixtures/egui-migration/` as an intentional versioned change and
run the repository-targeted finalization commands:

```powershell
pnpm egui:fixtures:write
pnpm check:egui-fixtures
git diff -- src-tauri/tests/fixtures/egui-migration
```

The default `egui:fixtures:write` command rewrites generated text fixtures and
`manifest.json`; do not run it before the Rust artifacts have been reviewed and
promoted. The default check is read-only.

## Formal baseline

Build the production shell, then run every scenario into the gitignored staging directory. Do not
write the first result directly into `docs/egui-migration/baselines/`: a formal build manifest
binds the complete Git worktree, so that new untracked file would correctly invalidate every
later scenario from the same build.

```powershell
pnpm tauri:build:win:x64
$staging = "$PWD\.local\egui-baselines"
$executable = "$PWD\src-tauri\target\x86_64-pc-windows-msvc\release\aio-coding-hub.exe"
$scenarios = @(
  "startup-cold-process",
  "startup-warm-process",
  "first-interactive",
  "visible-idle",
  "hidden-tray",
  "logs-10k",
  "gateway-load"
)
New-Item -ItemType Directory -Force $staging | Out-Null

foreach ($scenario in $scenarios) {
  $output = Join-Path $staging "tauri-win32-x64-$scenario-0.60.13.json"
  pnpm baseline:tauri -- `
    --executable $executable `
    --fixture current `
    --scenario $scenario `
    --warmups 2 `
    --runs 10 `
    --output $output
  if ($LASTEXITCODE -ne 0) { throw "baseline failed: $scenario" }
}
```

Failed measured runs are preserved with `status: "diagnostic"`; the command exits non-zero and
that file must stay out of the registry. Only after every required scenario has produced
`status: "complete"` may the unchanged staged files be promoted together. Run the read-only
preflight first, then use the separate explicit promotion command:

```powershell
pnpm egui:baseline:preflight
pnpm egui:baseline:promote
```

Preflight is read-only and uses the complete result validator on every direct staged JSON file. It
requires each of the seven scenarios exactly once, binds every filename to the validated
platform, architecture, scenario, and app version, rejects in-progress markers, and requires one
repository/build/database/machine/protocol identity across the matrix. It requires the canonical
settings hash to match across all non-hidden scenarios while allowing `hidden-tray` to retain its
documented `start_minimized=true` runner-owned overlay hash. It also rejects every destination
that already exists. Promotion repeats the complete preflight before changing either directory, then
publishes every destination as an independently copied, exclusively created file and rechecks its
preflight SHA-256 before removing any staged source. A publish or source-removal failure rolls the
matrix back instead of leaving an intentionally partial promotion.

`pnpm check:egui-baseline-registry` is the CI-safe registry check. An empty registry is valid while
real platform runs are pending. Once results exist, it validates every file with the same complete
validator and requires every platform/version/build group it discovers to contain all seven
scenarios exactly once. It never treats the entire registry as one seven-file matrix, so future
platforms and versions can coexist.

Promotion changes the Git worktree and intentionally ends the validity window of that build
manifest. Rebuild before collecting any additional scenario. The runner refuses outputs outside
the direct `.local/egui-baselines/` staging directory, debug executables, fewer than two warmups,
fewer than ten measured runs, unsupported fixtures, non-JSON paths, output overwrite, and a
pre-existing `<output>.inprogress` marker. It creates the marker before the first warmup and
removes it only after a schema-valid result has been atomically published. Errors and external
interruption retain the marker; it is diagnostic evidence and must never be promoted. Check its
PID is no longer running, preserve it if needed, then remove it explicitly before retrying that
output path. The runner creates a new isolated temporary home for every cold run and only
terminates the exact process identities proven to descend from the process it launched.

## Migration use

- C1/C2 consume `compatibility-contract.json` as the current-shell boundary while extracting the headless Rust core.
- C3 must use the same fixtures, actions, gateway stub, sample counts, and machine when comparing the egui prototype.
- A contract change is allowed only with a source change, updated tests, a regenerated snapshot, and an explicit compatibility review.
- Absolute results from different machines or operating systems must never be pooled into one aggregate.
